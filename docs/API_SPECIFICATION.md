# API_SPECIFICATION

Base path: `/api/v1`. The authoritative schema is **generated by FastAPI** — open the
running app at `/docs` (Swagger UI) or fetch `/openapi.json` (OpenAPI 3.1.0, title
"RoadGuard AI", version 0.1.0). The tables below are read from that live schema; they
are not hand-maintained.

## Conventions

- **Mutations require a CSRF header.** Every POST/DELETE must send
  `X-RoadGuard-Client: web`; without it the request is rejected `403`. No CSRF token
  ever appears in the DOM (R8).
- **Auth is a server-side HttpOnly cookie.** `SameSite=Lax`; `Secure` in production.
  The client cannot read the token; role checks happen server-side.
- **Typed errors only.** Failures return `{"code": <ErrorCode>, "message": ...}` with a
  proper status. There are no silent fallbacks (R3). `ErrorCode` values:
  `invalid_input` (400), `insufficient_evidence` (422), `provider_unavailable` (502),
  `auth_failure` (401), `authz_failure` (403), `model_unavailable` (503),
  `rate_limited` (429, with `Retry-After`), `not_found` (404), `internal_error` (500).
- **Strict request bodies.** `StrictModel` sets `extra="forbid"`; unknown fields are a
  `400`, not silently dropped.

## Key request/response shapes

**`POST /auth/register`** — body `{email, password}` only (no display name field; extra
keys are rejected). Password validated (`validate_password`); duplicate email → `400`.

**`POST /routes/analyze`** — body carries route waypoints + optional `speed_kmh` /
`road_class` / `grade_pct` context. Response lists per-route score, coverage,
`ranking_basis: "not an accident-risk ranking"`, per-section geometry challenge scores
each tagged with provenance and `model_status`. Low-coverage routes return
`insufficient_evidence` rather than a number.

**`POST /hazards`** — body `{category ∈ [pothole, debris, waterlogging,
poor_visibility, sharp_curve, road_work, other], description ≤500, lat, lon,
source ∈ [current_location, map_pin]}`. Created as `unverified` with a 24 h TTL; the
UI never labels an unverified report "confirmed" (R6).

**`POST /admin/hazards/{id}/moderate`** — body `{action ∈ [verify, reject], note ≤500}`.
Writes an `audit_log` row with action `hazard_verified` / `hazard_rejected`. Only open
(`unverified`/`verified`) hazards can be moderated.

## Provenance in responses

Every scored section carries the evidence channel that produced it and the assumption
used when context was missing (e.g. speed band assumed from road class, flagged
`speed_missing`). This is what makes the API outputs defensible: no number appears
without a stated basis (R7).
